# Транспорты

Telepath может общаться с вами через **Telegram**, **Slack** или **оба** одновременно.
Транспорт — это лишь фронтенд для сообщений; ядро (агенты, разрешения, git-ветки,
нормализованный поток событий) одинаково, какой бы вы ни выбрали. Транспорт задаётся
настройкой `TRANSPORT` (`telegram` | `slack` | `both`, по умолчанию `telegram`).

## Публичный IP не нужен

Оба транспорта подключаются **только по исходящему соединению** и работают за NAT без
webhook, входящего порта и публичного URL:

- **Telegram** использует long-polling.
- **Slack** использует **Socket Mode** (WebSocket, который открывает бот к Slack).

Это ключевое свойство Telepath: его можно запустить на ноутбуке или домашнем сервере
и управлять им с телефона.

## Telegram или Slack

| | Telegram | Slack |
|---|----------|-------|
| Подключение | long-polling | Socket Mode (WebSocket) |
| Токены | один токен бота | токен бота `xoxb-` + токен уровня приложения `xapp-` |
| Запуск задачи | любое сообщение или `/<agent> …` | `@Telepath …`, личное сообщение или `/telepath …` |
| Команды | `/help`, `/perm`, … | `/telepath help`, `/telepath perm …`, … |
| Статус в реальном времени | одно редактируемое сообщение | одно редактируемое сообщение (в треде) |
| Подтверждения | inline-кнопки Approve/Deny | кнопки Approve/Deny в Block Kit |
| Allowlist | ID чатов | ID пользователей и/или ID каналов |

Команды соответствуют друг другу **1:1** в обоих транспортах. В Slack они являются
подкомандами единственной slash-команды `/telepath` (см. [Команды Telegram](telegram-commands.md),
где описаны оба варианта).

## Оба транспорта одновременно

Установите `TRANSPORT=both` и укажите учётные данные и для Telegram, и для Slack.
Telepath запускает оба фронтенда поверх одного и того же движка, агентов и
`PROJECTS_DIR`. Так как все диалоги используют одно рабочее дерево, задачи по-прежнему
выполняются последовательно глобально — одна задача за раз во всех чатах Telegram и каналах
Slack. Состояние каждого диалога (выбранный агент, режим разрешений, режим веток)
хранится по ключу `transport:conversation`, поэтому чат Telegram и канал Slack
никак не мешают друг другу.

## Как выбрать

- Вы один, работаете с телефона → **Telegram** быстрее всего настроить (один токен).
- Ваша команда уже работает в Slack или вы хотите, чтобы подтверждения были видны
  в канале → **Slack**.
- Вы мигрируете или хотите охватить обе аудитории → **оба**.

Пошаговую настройку каждого из них см. в разделе [Начало работы](getting-started.md).
