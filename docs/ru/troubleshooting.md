# Устранение неполадок

Установите `LOG_LEVEL=debug`, чтобы получить больше подробностей. Ниже приведены типичные сбои.

## «Agent is not installed»

`/agents` показывает ✅/❌ для каждого агента. Если у вашего стоит ❌:

- Убедитесь, что CLI доступен в PATH (`claude --version`, `gemini --version`,
  `codex --version`, `aider --version`).
- Если он находится в нестандартном месте, задайте соответствующую переменную `*_BIN`
  (`CLAUDE_BIN`, `GEMINI_BIN`, `CODEX_BIN`, `AIDER_BIN`) с полным путём к нему.
- В Docker используйте самодостаточный образ (в нём уже есть CLI) или смонтируйте их
  в облегчённый образ.

## Бот не отвечает

- **Токен:** проверьте `TELEGRAM_BOT_TOKEN`. При запуске Telepath проверяет токен
  в Telegram; неверный токен приводит к быстрому сбою.
- **Allowlist:** ваш chat ID должен быть в `ALLOWED_CHAT_IDS`. Чаты вне списка
  игнорируются молча (см. предупреждение в логах).
- **Подключение:** Telepath использует исходящий long-polling; убедитесь, что хост
  может обращаться к `api.telegram.org`.
- **Запуск в другом месте:** только один процесс бота должен выполнять long-polling
  для данного токена одновременно.

## Отказ «Working tree is dirty»

В режиме `per-task` Telepath отказывается запускать задачу, если в `PROJECTS_DIR` есть
незакоммиченные изменения. Либо закоммитьте/отложите их сами, либо задайте
`BRANCH_STASH_DIRTY=true`, чтобы Telepath отложил их автоматически.

## Таймаут подтверждения → отказ

В режиме `interactive`, если никто не нажмёт Approve/Deny в течение
`APPROVAL_TIMEOUT_SECONDS` (по умолчанию 120), запрос **отклоняется**, и агенту
сообщается об этом. Увеличьте таймаут, если нужно больше времени, или используйте `allowlist`/`auto`,
если не хотите, чтобы вас спрашивали.

## Interactive не запросил подтверждение

Интерактивное подтверждение работает **только с Claude**. С gemini/codex/aider
`interactive` переключается на `allowlist`, а ответ сообщает фактически использованный
режим. Переключите чат на Claude командой `/use claude`, чтобы получить подтверждения в реальном времени.

## Задачи, похоже, ставятся в очередь

Все чаты используют один рабочий каталог `PROJECTS_DIR`, поэтому задачи **выполняются
последовательно** — по одной за раз во всех чатах, по одной на чат. Если рабочее пространство
занято, вы получите ответ «попробуйте снова». Используйте `/status`, чтобы увидеть, что выполняется,
и `/cancel`, чтобы остановить это.

## `/cancel` не убил всё (Windows)

Telepath убивает **дерево** процессов агента по мере возможностей — `taskkill /F /T` в
Windows, `SIGKILL` для группы процессов в Unix. Глубоко вложенные вспомогательные процессы
иногда могут остаться; если процесс Node выжил, проверьте Диспетчер задач.

## `/resume` сообщает, что нечего продолжать

Последний ID сессии и её директория проекта хранятся **в памяти** и теряются
при перезапуске Telepath. После перезапуска продолжать нечего. Resume также работает
**только для Claude**; другие агенты сообщают, что это не поддерживается.

## Ошибка коммита

Если в репозитории не задана git-идентификация, Telepath коммитит с запасной
идентификацией `Telepath <telepath@localhost>`, чтобы коммит в ветку задачи всё равно
прошёл. Если коммит всё же не удаётся, ошибка показывается в итоговом отчёте —
проверьте состояние git репозитория и права доступа.
