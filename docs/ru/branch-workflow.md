# Рабочий процесс с ветками

Telepath полностью управляет git. Собственные git-функции агентов и автокоммиты
отключены, чтобы управление версиями было согласованным и безопасным. Режим задаётся
через `BRANCH_MODE`.

## `per-task` (по умолчанию)

Каждая задача выполняется в собственной изолированной ветке:

1. **Предварительная проверка.** Рабочее дерево должно быть чистым. Если оно загрязнено,
   Telepath отказывается с понятным сообщением — если только `BRANCH_STASH_DIRTY=true`, тогда
   он сначала откладывает (stash) изменения. Он запоминает базовую ветку и SHA базового коммита.
2. **Создание ветки.** Создаётся и переключается ветка с именем
   `<BRANCH_PREFIX><slug>-<yymmdd-hhmm>`, например
   `telepath/add-health-endpoint-260115-1430`. Slug формируется из текста задачи
   (в нижнем регистре, символы, не являющиеся буквами или цифрами, сворачиваются в `-`, затем
   обрезается).
3. **Запуск агента.** Агент только редактирует файлы; его git отключён.
4. **Коммит в ветку.** При успехе, если `BRANCH_COMMIT=true` (по умолчанию), Telepath
   добавляет всё в индекс и делает коммит **в ветку задачи** с сообщением, которое
   представляет собой краткое описание задачи и трейлер:

   ```
   <summary>

   via Telepath (<agent>)
   ```

   Если изменений нет, Telepath сообщает об этом и коммит не создаёт.
5. **Никогда не трогать main.** Telepath никогда не делает push, merge, rebase, принудительных
   операций любого рода и не коммитит в `main`/`master`.
6. **Отчёт.** Telepath публикует имя ветки, SHA коммита, `git diff <base>..HEAD
   --stat` и полный дифф в виде документа `.diff`, с кнопками **Keep branch** /
   **Delete branch & restore base**.

Вы проверяете ветку и **сами делаете merge/push**.

### Компромисс при `BRANCH_COMMIT=false`

Если `BRANCH_COMMIT=false`, изменения агента остаются **незакоммиченными** в ветке
задачи. Telepath сообщает вам об этом. Поскольку все чаты используют одно рабочее дерево,
незакоммиченные изменения обеспечивают более слабую изоляцию: предварительная проверка
следующей задачи увидит загрязнённое дерево и откажется (или отложит изменения). Лучше оставить
значение по умолчанию `true`, если у вас нет особой причины.

## `off`

Telepath работает в текущей ветке, не создаёт ветку и не делает коммитов. Вы по-прежнему
получаете живой поток и **диф рабочего дерева в конце запуска**. Это устаревший/минимальный
режим для случаев, когда вы управляете ветками сами.

## Жёсткие защитные механизмы

Каждая git-команда проходит через единый защитный слой (`internal/git/guard.go`), который
**отказывает** в:

- `push`, `merge`, `rebase`, `pull`, `fetch`, `cherry-pick`, `revert`
- любом `--force` / `-f` / `--force-with-lease`
- `reset --hard`
- коммите в `main` / `master`, создании или удалении этих веток

**Гарантия: `main` и удалённый репозиторий никогда не изменяются. Худшее, что может сделать
задача, — оставить проверяемую локальную ветку.**

## Очистка

- **Keep branch** оставляет ветку для вашей проверки.
- **Delete branch & restore base** отбрасывает изменения ветки задачи, возвращает
  базовую ветку и удаляет ветку задачи. (Отказывает, пока задача выполняется — сначала `/cancel`.)
- `/branches` в любой момент показывает существующие ветки `telepath/*`.
