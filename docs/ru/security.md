# Безопасность

Telepath запускает настоящих coding-агентов на вашей машине, поэтому важно понимать модель доверия.

## Allowlist chat ID

Telepath действует только в чатах, перечисленных в `ALLOWED_CHAT_IDS`. Allowlist
применяется к **каждому обновлению — и к сообщениям, и к нажатиям кнопок** — до того, как
происходит что-либо ещё. Telepath **отказывается запускаться** без хотя бы одного разрешённого
chat ID и молча игнорирует любой чат вне списка. Храните токен бота в секрете: любой, у кого он есть,
может писать вашему боту, но действия выполняются только в чатах из allowlist.

## Агенты используют собственные учётные данные

Каждый CLI агента проходит аутентификацию по **собственному** API-ключу или логину,
которые хранятся на хосте согласно документации этого агента. Telepath никогда не читает,
не хранит и не передаёт эти учётные данные — он лишь запускает CLI. Единственные секреты,
которые Telepath хранит сам, — это токен Telegram-бота и allowlist чатов.

## Оговорка про `auto` (пропуск разрешений)

В режиме `auto` агент работает с отключёнными запросами разрешений — он может
редактировать файлы и выполнять shell-команды без вопросов. Это удобно, но мощно.
Предпочтительнее:

- `allowlist` — страховка, которая тоже не требует постоянного присмотра, или
- `interactive` (Claude), если вы хотите видеть и подтверждать каждый рискованный шаг.

См. [Разрешения](permissions.md).

## Осведомлённость о prompt-инъекциях

Coding-агент читает файлы вашего репозитория и текст задачи. Вредоносное содержимое в любом
из них (отравленный файл, специально составленная задача) может попытаться направить агента
на нежелательные действия. Меры защиты:

- Используйте `allowlist` или `interactive` для репозиториев, которым вы не доверяете полностью.
- Проверяйте ветку задачи перед merge — на этом и построен рабочий процесс.
- Помните, что запрещённый набор блокирует `curl`/`wget`/`WebFetch`, `rm`, `git push` и т. д.
  в режиме `allowlist`.

## Гарантия git

Telepath управляет всем git через единый защищённый путь кода, который **никогда** не делает
push, merge, rebase, принудительных операций любого рода или коммит в `main`/`master`.
Удалённый репозиторий и ваша основная ветка никогда не изменяются. **Худший
сценарий любой задачи — это проверяемая локальная ветка**, которую вы решаете сохранить или
удалить. См. [Рабочий процесс с ветками](branch-workflow.md).

## Сетевая конфигурация

Telepath общается с Telegram через **long-polling** (только исходящие соединения), поэтому
работает за NAT без публичного IP, webhook или входящего порта. MCP-сервер
интерактивного подтверждения привязан **только к loopback** (`127.0.0.1`) на случайном порту на
время одного запуска.
